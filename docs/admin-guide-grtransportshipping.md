# מדריך למתקין ולמנהל — מודול grtransportshipping

מודול PrestaShop שמתמחר משלוח חבילות בתוך יוון לפי מסלולי תחבורה ציבורית
(KTEL, מעבורות, ובמידת הצורך טיסות פנים), במקום תעריף קבוע או תעריף לפי משקל.
הלקוח מזין כתובת יעד — והמחיר נקבע לפי המסלול שמשרת את היעד.

## איך זה עובד, בקצרה

- המודול רושם Carrier אחד בחנות: **Greek transport — station pickup**.
- לכל יעד יש שורת Route בטבלת המסלולים של המודול: מאיפה יוצאים (Origin),
  לאיזו תחנה מגיעים (Station), ולאיזה אזור היעד שייך — לפי קידומת מיקוד
  (Postal prefix) או לפי שם עיר.
- בצ'קאאוט, כשהלקוח מזין כתובת ביוון, המודול מחפש Route שתואם את היעד:
  קודם לפי קידומת המיקוד, ואם אין התאמה — לפי שם העיר, בהתאמה שאינה רגישה
  לטונוס (Αθήνα‏ = Αθηνα). אם נמצא Route — המחיר שלו הוא מחיר המשלוח.
  אם לא נמצא — הלקוח רואה את ההודעה:
  "No priced transport route matches this destination."
- רוב היעדים הם **Station pickup only**: החבילה מחכה בתחנה/בנמל, לא מגיעה
  עד הדלת. ה־Notice של המסלול הוא הטקסט שהלקוח רואה על כך.

## התקנה

1. מתקינים את המודול מקובץ ה־release או מתיקיית הריפו (התיקייה
   `grtransportshipping` לתוך `modules/`), ואז ב־back office:
   Module Manager ← grtransportshipping ← Install.
2. בהתקנה נוצר ה־Carrier ונטענים נתוני Demo (מסומנים `demo = 1`).
3. מוודאים שה־Carrier פעיל (active) ומשויך לאזורי המשלוח הרצויים
   (ברירת מחדל: Greece / Europe zone לפי החנות).

**חשוב — נתוני ה־Demo אינם תעריפים רשמיים.** קובץ הנתונים עצמו מצהיר:
"Illustrative parcel shipping assumptions, NOT official KTEL/ferry/air
cargo tariffs." עשרת מסלולי ה־Demo (Athens→Patras ‏€12.50, ‏Athens→Thessaloniki
‏€18.00, ‏Piraeus→Naxos ‏€29.00 ועוד) הם דוגמאות להמחשה ולבדיקה — לפני שימוש
אמיתי בחנות מחליפים אותם במסלולים ובמחירים מאומתים.

## טבלת המסלולים (Routes) — השדות

| שדה | משמעות |
|---|---|
| Mode | bus / ferry / flight |
| Origin name | תחנת המוצא, למשל Athens Kifisos KTEL |
| Station name | תחנת היעד שבה הלקוח אוסף |
| City | שם עיר להתאמה לפי שם (ריק = התאמה לפי מיקוד בלבד) |
| Postal prefix | קידומת מיקוד של אזור היעד, למשל 262 לפטרס |
| Price | מחיר המסלול ב־€ (קלט "12,50" נשמר כ־12.50) |
| Pickup only | 1 = איסוף בתחנה בלבד |
| Route status | available / מושבת — מסלול מושבת לא יוצע ללקוחות |
| Notice | טקסט ללקוח על המסלול (איסוף, תיאום מראש, תלות במזג אוויר) |
| Verified at / Verified by | מתי ועל ידי מי המחיר אומת מול המפעיל |

## עבודה שוטפת

- **הוספת יעד חדש:** שורת Route חדשה — תחנה, קידומת מיקוד (או עיר), מחיר,
  Notice ברור ללקוח. מרגע השמירה היעד מתומחר בצ'קאאוט.
- **שינוי מחיר:** עורכים את שורת המסלול. מומלץ לעדכן באותה הזדמנות את
  Verified at — כך תמיד ברור מה המחיר האחרון שאומת ומתי.
- **השבתת מסלול** (שביתה, הפסקת קו, עונה): Route status ← מושבת. היעד
  יחזור להציג "אין מסלול מתומחר" עד ההפעלה מחדש.
- **מחיקת נתוני Demo:** אחרי שכל המסלולים האמיתיים הוזנו, מוחקים את שורות
  ה־`demo = 1` כדי שלקוחות לא יקבלו מחירי המחשה.

## מה הלקוח רואה

- יעד עם Route: אפשרות המשלוח של המודול עם המחיר המחושב, וביעדי Pickup —
  גם שם התחנה וה־Notice.
- יעד בלי Route: ההודעה "No priced transport route matches this destination."
  ושיטות משלוח אחרות של החנות (אם קיימות) ממשיכות כרגיל.
- שימו לב: מחיר סופי בצ'קאאוט עשוי לכלול תוספות של PrestaShop עצמה —
  למשל Handling charge ומע"מ — מעבר למחיר המסלול הגולמי. מחיר המסלול הוא
  הבסיס, לא בהכרח הסכום הסופי שמוצג.

## בתכנון

- דף בדיקת מחיר ללקוח בלי צ'קאאוט (Issue #62): הזנת מיקוד או עיר בעמוד
  שהבעלים בוחר (למשל FAQ), עם אותה תוצאת מחיר, ואפשרות לסמן את היעד במפה
  (OpenStreetMap). עד שזה ייבנה, הדרך לבדוק מחיר היא דרך הצ'קאאוט.

## פתרון תקלות מהיר

- **אין שום הצעת משלוח של המודול:** לבדוק שהמודול Installed + Enabled,
  שה־Carrier פעיל, ושהכתובת היא ביוון עם מיקוד תקין.
- **יעד מסוים לא מקבל מחיר:** לחפש בטבלת המסלולים אם קיימת שורה עם
  קידומת המיקוד או שם העיר, ושהיא בסטטוס available.
- **מחיר לא צפוי:** לבדוק שאין שורת Demo שנשארה פעילה לאותו יעד, ושמחיר
  המסלול הוא אכן המחיר המאומת האחרון (Verified at).
